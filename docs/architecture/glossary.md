# Glossary

Canonical terminology used in UI labels, API docs, runbooks, and metrics. Keep this file as the single source of truth — any copy that reaches a user or operator must match a term here.

## Core concepts

| Term                       | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Agent**                  | A managed AI work actor that may be container-backed or provider-backed. The DB table is `agents` (was `sessions` before migration 058).                                                                                                                                                                                                                                                                                                                                              |
| **Container CLI**          | The task-execution CLI running **inside** an agent's container (`claude` / `codex` / `gemini` / `opencode`). Persisted as `agents.cli_tool`. Alternative phrasings: _in-container CLI_, _agent CLI runtime_. **Never** just "CLI" on its own — that is ambiguous.                                                                                                                                                                                                                     |
| **Platform CLI**           | The `agentforge` binary that operators use to manage the platform itself (list agents, start/stop containers, query jobs, run migrations). Built from the `rust/crates/cli` crate. Alternative phrasing: _agentforge CLI_. Not to be confused with Container CLI.                                                                                                                                                                                                                     |
| **Provider+Prompt agent**  | An agent with `cli_tool = NULL` — no container, no terminal. Calls the LLM provider directly via the LLM gateway. The kind selector in `CreateAgentModal` calls this **Provider + Prompt**.                                                                                                                                                                                                                                                                                           |
| **Coding Plan provider**   | A gateway provider entry (key suffix `_coding`, e.g. `zhipu_coding`) for a China-region vendor's coding subscription product. Talks to the vendor's Anthropic-compatible endpoint and takes the subscription key — a separate product from the vendor's pay-as-you-go API key. See `docs/guides/configuration.md` for the endpoint matrix.                                                                                                                                            |
| **Participant**            | An agent registered for A2A orchestration. DB table `participants` (was `agents` pre-rename, hence the participant/agent distinction).                                                                                                                                                                                                                                                                                                                                                |
| **Team space**             | Beginner-facing name for the top-level account area where people, teams, projects, and agents are grouped. Backed by organization records in API and DB code. Use **Team space** in first-run and Admin UI labels; use **organization** only when naming API fields, DB tables, or diagnostics that require the implementation term.                                                                                                                                                  |
| **Task queue**             | The beginner-facing place where new tasks wait until an agent is ready to pick them up. Backed by an agent group/work lane in code and API contracts. Use **Task queue** in first-run, task-creation, and agent-management UI so non-specialist users know what will happen next.                                                                                                                                                                                                     |
| **Sidecar**                | Per-container NATS bridge that forwards hook events from Container CLIs to the backend. Lives in `rust/bins/sidecar`.                                                                                                                                                                                                                                                                                                                                                                 |
| **Worker bridge**          | The sidecar's inner event loop that subscribes to NATS assignments and forwards them to the Container CLI.                                                                                                                                                                                                                                                                                                                                                                            |
| **CLI agent image**        | The local image a container agent runs, tagged `agentforge-agent:<tool>` (e.g. `agentforge-agent:codex`). The auto-updater pulls the matching registry repo `${AGENT_REGISTRY}/agent-<tool>:<tag>` and re-tags it to that local ref, so the next spawn resolves the current CLI. `claude` has no public image and is never pulled — it uses the local image build instead.                                                                                                            |
| **Image auto-update**      | Deployment-side poller (off by default, `CLI_IMAGE_AUTO_UPDATE_ENABLED`) that pulls newer `agent-<tool>` overlays on an interval so the next spawn runs the current CLI. For `claude` the same sweep runs the local image build check instead of a pull. Running agents are untouched. Status: `GET /api/v1/admin/cli-images` (admin-only).                                                                                                                                           |
| **Local image build**      | How `claude` stays current (its license forbids a public registry image): the sweep diffs npm's latest `@anthropic-ai/claude-code` against the version label on the local `agentforge-agent:claude` image and surfaces `update_available`; the image is then built server-side via one click in the admin panel (`POST /api/v1/admin/cli-images/claude/build`, admin-only) or automatically with `CLI_IMAGE_CLAUDE_AUTO_BUILD=true`. Image-level only — running agents are untouched. |
| **Image prune**            | Safe disk reclaim inside the auto-update loop (off by default, `CLI_IMAGE_PRUNE_ENABLED`) that removes only our own dangling overlays no container references. Never stops or removes containers; safe on shared Docker hosts.                                                                                                                                                                                                                                                        |
| **Image roll**             | Operator action that moves idle running agents onto the latest image by stopping and respawning their containers (`POST /api/v1/admin/cli-images/{tool}/roll`, admin-only). Working agents are skipped (`skippedBusy`); an agent whose respawn fails is left stopped and surfaced for manual restart. Each agent rolls within its own tenant scope.                                                                                                                                   |
| **Join command**           | The single copy-paste command (one per OS) that connects a Local CLI agent: it fetches the bootstrap script from the deployment, downloads `agentforge-sidecar` if missing, exchanges the join code for credentials, and starts the sidecar. Returned by `POST /api/v1/agents/local-enroll` and shown in the Create Agent dialog.                                                                                                                                                     |
| **Join code**              | Short-lived pairing code (`afj_…`, 15-minute TTL) embedded in the join command. Stored only as a SHA-256 hash (`agent_join_codes`); claimable until expiry via the public `POST /api/v1/agents/local-join/claim` endpoint, where the code itself is the credential.                                                                                                                                                                                                                   |
| **Code Repository Access** | Settings entry for GitHub or GitLab HTTPS repository access keys. Use this label when the repository address starts with `https://`, and explain that GitHub/GitLab may call the key a personal access token.                                                                                                                                                                                                                                                                         |
| **git@ Repository Access** | Settings entry for repository access that uses addresses starting with `git@`. Use this label in navigation and first-run guidance so operators can choose the right setup path by matching the repository address prefix. Keep detailed SSH safety guidance inside the form and error text.                                                                                                                                                                                          |

## Runtime modes (Settings page)

| Label                        | Meaning                                                                                                                |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Host CLI (local process)** | `runtime = cli` — the Container CLI is spawned as a local OS process on the host, not in a container. Legacy dev mode. |
| **API (direct LLM calls)**   | `runtime = api` — used by provider+prompt agents; no CLI involved at all.                                              |
| **Container (Docker)**       | `runtime = container` — default. Container CLI runs inside a Docker container managed by the platform.                 |

> The DB column `agents.runtime_kind` and the Rust enum `agentforge_core::RuntimeKind` use the values `container`, `cli`, and `api` shown in the Meaning column above. See `docs/superpowers/specs/2026-05-27-host-cli-enrollment-design.md` for the discriminator design.

## UI copy rules

- **Always qualify "CLI"** in UI strings. Prefer "Container CLI" or "Platform CLI" (or a more specific runtime label) over bare "CLI".
- **Field names stay unchanged**: `cli_tool`, `cliTool`, `CLI_TOOLS` etc. are schema/code identifiers, not display strings. Do not rename them purely for UI clarity — it churns the DB + every client without buying anything.
- **Vendor product names stay as vendors use them**: "Claude Code", "Gemini CLI" — don't prefix with "Container CLI:" in product selectors; the grouping surface (the dropdown's own label) already establishes context.

## When to add a term

Before introducing a new term in UI / docs / metrics: check this file. If the concept exists, use the term from here. If it doesn't, add it here **before** shipping the first caller so we don't create a second synonym.
