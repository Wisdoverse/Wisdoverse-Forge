# Dependency Security Policy

## Scanning

CI runs on every MR:

- `npm audit` — npm dependencies
- `trivy fs` — all filesystem dependencies
- `cargo audit` — Rust crate dependencies (advisory DB via RustSec)

Renovate auto-creates MRs for updates (see Issue #1 Dependency Dashboard).

## Severity SLA

| Severity | Pipeline | Fix deadline     | Action                              |
| -------- | -------- | ---------------- | ----------------------------------- |
| CRITICAL | Blocks   | 24 hours         | Patch immediately, hotfix if needed |
| HIGH     | Blocks   | 7 days           | Prioritize in current sprint        |
| MEDIUM   | Warns    | 30 days          | Schedule in backlog                 |
| LOW      | Warns    | Next maintenance | Bundle with other updates           |

## Update Procedures

- `npm audit fix` for npm vulnerabilities (verify with `npm audit --json`)
- `cargo update -p <crate>` for Rust deps (verify with `cd rust && cargo audit`)
- Always run full test suite (`npm run test:unit` and `cd rust && cargo test --workspace`) after dependency updates
- Renovate MRs: review changelog, merge if CI passes, close if superseded by manual fix

## Operator-installed artifacts

All published release artifacts (sidecar binary, Platform CLI) are signed via
Sigstore keyless cosign on every GitHub release. Each artifact ships alongside:

- `<artifact>.sig.bundle` — Sigstore bundle containing the cosign signature and
  OIDC transparency-log entry.
- `<artifact>.sbom.json` — Software Bill of Materials in CycloneDX JSON format,
  generated by syft.

The OIDC signing identity is bound to the official `release-supply-chain.yml`
GitHub Actions workflow **and** the specific release tag. A binary signed by a
fork, a different workflow file, or a different tag will fail verification even
if the bytes are identical.

Operators in environments where binary provenance is required MUST verify
signatures before running artifacts:

```bash
# Install cosign once: https://docs.sigstore.dev/cosign/installation/
agentforge verify --tag <release-tag> <artifact>
```

For the full operator verification path, see
[docs/runbooks/host-cli-agent-enrollment.md](../runbooks/host-cli-agent-enrollment.md).
