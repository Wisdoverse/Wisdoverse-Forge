## Unreleased

### Upgrade Notes

- **self-host (breaking):** the `prod` Compose override now requires
  `ORCHESTRATOR_DB_PASSWORD` and no longer falls back to the well-known
  default. Existing self-contained installs must set it to the value the
  orchestrator database was created with, which is `orchestrator` unless you set
  your own. Then start as usual. `make bootstrap-selfhost` generates it for new
  installs. `make prod-ext` and `make dev` are unchanged. Steps and safe
  rotation: [Self-host operator runbook](docs/runbooks/self-host-ops.md#upgrade-step-orchestrator-database-password-is-now-required).
- **self-host (behavior change):** after upgrading, NATS (client and
  monitoring ports), Temporal and its UI, the bundled database and Redis,
  Casdoor, the image registry, Adminer and Redis Commander are reachable only
  from the host itself. Host CLI agents on other machines need
  `NATS_BIND_ADDRESS` set. `make dev` no longer publishes the API on every
  address when `BIND_ADDRESS` is unset. Lines that restore the old exposure on
  IPv4, and an optional override file for IPv6:
  [Self-host operator runbook](docs/runbooks/self-host-ops.md#upgrade-step-internal-ports-now-listen-only-on-this-machine).

### Bug Fixes

- **organizations:** only owners and administrators can rename an
  organization. Before this change any member, including a viewer, could rename
  an organization they belonged to, although the role controls this and the
  settings page already offered the rename to owners and admins only.
  `PATCH /api/v1/organizations/{id}` and `PATCH /api/v1/orgs/{id}` now refuse a
  member without the owner or admin role with HTTP 403 and error code
  `FORBIDDEN`; a non-member still gets HTTP 404 `NOT_FOUND`. This is a defect fix
  under the Enforcement Corrections rule in
  [docs/versioning.md](docs/versioning.md#enforcement-corrections) (#1324).
- **orchestrator:** a workflow no longer stays `running` forever when its
  Temporal execution is gone (#1352). A new reconciler, on by default
  (`ORCHESTRATOR_WORKFLOW_RECONCILE_ENABLED`), ends such rows: a finished
  recorded run sets the matching status (cause `reconciled_from_temporal`), and
  an execution that stays missing for at least
  `ORCHESTRATOR_WORKFLOW_RECONCILE_GRACE_SECS` (default 600) is marked `failed`
  with cause `execution_lost` and can be re-run. "Not found" is only trusted
  for workflows started in the same Temporal namespace (its id is now
  recorded); older rows need `ORCHESTRATOR_WORKFLOW_RECONCILE_TRUST_CURRENT_TEMPORAL`.
  Cancel on a missing execution now succeeds (cause `execution_missing`),
  signal returns `409` with code `workflow_execution_not_running` instead of an
  internal error, and a status read returns `executionState`. The reconciler
  starts even when Temporal is down at boot and connects once it is back. A
  late finalizer or a delayed cancel of an earlier run can no longer overwrite
  a re-run. Orchestrator migration `014_workflow_execution_reconcile.sql` adds
  the nullable columns and a `state_version` column that its trigger
  increments on every change except reconciler bookkeeping.
- **backup:** the `backup` profile now dumps the orchestrator and Temporal
  databases along with the API database. It passes each password to `pg_dump`;
  the old command set only `POSTGRES_PASSWORD`, which `pg_dump` does not read.
  A failed dump of any database fails the run visibly, publishes no partial set,
  and keeps older backups. `BACKUP_ONCE=1` runs one pass for manual backups. A
  lock file serializes runs, and each run stages its dumps in its own folder.
  Stopping or interrupting a run ends it within seconds, removes its staging
  folder, and frees the lock.
  The bundled orchestrator database has resource limits. The
  [Disaster Recovery guide](docs/guides/disaster-recovery.md) restores in five
  fail-fast phases into fresh databases, says what a restore does and does not
  recover, and records a synthetic mechanics rehearsal. An application-level
  restore drill is still open.
- **db:** the server no longer refuses to start on a database first created by
  the legacy backend that still has the old `team_invites` table. Migration 089
  skipped that table and then failed with
  `column "token_hash" does not exist`. Before migrating, the server now moves
  the old table, with its rows,
  to the `legacy_pre_089` schema. Fresh databases and databases already past
  migration 089
  are unchanged. See [ADR 0006](docs/adr/0006-sqlx-migration-policy.md) and
  the [deployment guide](docs/guides/deployment.md#migrations).
- **observability:** the SLO runbook described orchestrator success rate,
  workflow start latency, NATS event delivery, DB pool saturation and WebSocket
  backlog indicators, targets and alerts on metrics that no service emits. They
  are now listed under
  [Not Implemented Indicators](docs/runbooks/observability-slo.md#not-implemented-indicators),
  and the alert table lists only the shipped rules with their pending periods
  and the external exporters three of them need.
  `agentforge_orchestration_assignment_publish_seconds` and
  `agentforge_orchestration_result_apply_seconds` are now exported as
  histograms (`_bucket`, `_sum`, `_count`, buckets 5 ms to 60 s) instead of
  summaries; their `quantile` series are gone. This is what the shipped
  `OrchestrationResultApplyLag` alert and the orchestration release-gate
  latency panels always queried, so that alert can now fire and the panels
  render. The release-gate metric-presence panels now check `_count`.
  `npm run metrics:contract` now also checks the runbook, every metric in the
  alert rules and dashboards (not only Forge-prefixed names), the series type
  (counter, gauge, histogram with or without buckets), and only counts
  recording macros in production code. CI also runs `npm run proto:check` with
  a pinned `protoc` 3.21.12, and the check now also fails on new untracked
  generated files.
- **self-fix:** the in-app **Finish this fix** action could merge a
  maintenance change although the latest verdict on its current report was a
  recorded human rejection. `POST /api/v1/self-fix/tasks/{id}/approve` now
  refuses that merge with HTTP 409 and error code
  `errors.maintenance.merge_rejected`. This is a defect fix under the
  Enforcement Corrections rule in
  [docs/versioning.md](docs/versioning.md#enforcement-corrections). See the
  [Maintenance delivery guide](docs/guides/maintenance-delivery.md#when-forge-refuses-to-merge-a-rejected-revision).
  The following refusals are the mechanism that keeps this rejection gate
  correct under concurrency, not separate exceptions:
  - `POST /api/v1/self-fix/tasks/{id}/decisions` returns HTTP 409
    `errors.maintenance.merge_in_progress` while a merge is in progress or
    unconfirmed.
  - A second concurrent finish returns HTTP 409 `errors.self_fix.merge_running`.
  - An unconfirmed attempt returns HTTP 409 `errors.self_fix.merge_unconfirmed`
    inside the 30-second settle window.
  - At the attempt limit it returns HTTP 400
    `errors.self_fix.merge_attempts_exhausted_unconfirmed`.
- **api:** `POST /api/v1/voice/transcribe` and `GET /api/v1/agents/{id}/git`
  now return HTTP 501 with error code `NOT_IMPLEMENTED` instead of a success
  response with empty data. Neither feature is implemented yet. This is a
  defect fix under the False-Success Corrections rule in
  [docs/versioning.md](docs/versioning.md#false-success-corrections).
- **CLI:** the Platform CLI no longer repeats non-idempotent requests (such as
  `agentforge agents prompt`) after a 429; it shows the server's error and any
  `Retry-After` hint instead. GET/DELETE are still retried.
- **CLI (compatibility):** API errors in the `{ error: { code, message } }`
  envelope now show their code and message instead of a bare `HTTP <status>`,
  and use the documented exit codes. Before, every such error exited `1`. Now
  `VALIDATION_ERROR` exits `2`, `UNAUTHORIZED`/`INVALID_API_KEY` exit `3`,
  `NOT_FOUND` exits `4` and `FORBIDDEN` exits `5`. Every other code, including
  `provider_rate_limited`, still exits `1`. Scripts that test for exit code `1`
  specifically should test for any non-zero exit code instead. See
  [Exit Codes](docs/guides/cli-platform-support.md#exit-codes).
- **api:** provider errors before a prompt stream starts no longer return 500:
  rejected provider credentials and rejected provider requests return 422 with a
  stable code, provider rate limits return 429 with a bounded `Retry-After`.
  The earlier 500 was an unclassified failure; see
  [Misclassified Internal Errors](docs/versioning.md#misclassified-internal-errors).
- **CLI:** use the registered `/api/health` readiness route for health and
  version commands; show the supported readiness status without assuming the
  endpoint provides version or uptime fields.
- **maintenance:** preserve source records during migration 104 and remove
  them with their task after explicit deletion, retaining tenant constraints.
- **self-fix:** rebuild and open draft PRs against the repository's observed default
  branch instead of assuming `main`; refuse archived/disabled repositories and
  missing Contents/Pull requests write grants before clone/push.

### Deprecated

- **api:** `POST /api/v1/voice/transcribe` and `GET /api/v1/agents/{id}/git`
  are deprecated. They have no implementation and no replacement, so the
  90-day [deprecation window](docs/versioning.md#deprecation-window) starts on
  the date this deprecation is published: 2026-11-22. Both endpoints stay
  callable (returning HTTP 501) through 2027-02-20. Removal release: the first
  release on or after 2027-02-21.

### Security

- **compose:** publish every port except the Caddy reverse proxy on an explicit
  host address: `BIND_ADDRESS` (default `127.0.0.1`) for internal services and
  tools, plus `NATS_BIND_ADDRESS` and `CASDOOR_BIND_ADDRESS`. The Docker
  baseline check now fails when a published port in any tracked Compose file
  does not default to a loopback host address. See
  [Which ports are reachable](docs/guides/deployment.md#which-ports-are-reachable-from-other-machines).
- **tenancy:** by-id writes for memory items, skills, context feedback and
  candidates, MCP Agent leases, Agent collaborators, group members and task runs
  now carry the organization in their own SQL, so a missed caller check cannot
  change another organization's row; a foreign id behaves like an unknown id.
  Background work builds its scope through one named constructor
  (`TenantScope::for_background`), and the scope-construction guard now
  allowlists single functions and rejects aliases, wrappers and split paths.
  Defense in depth; no cross-tenant access is known (#1324).
- **self-fix:** constrain authenticated GitHub requests to the configured API
  origin, refuse redirects, and require review for changes to verification and
  maintenance policy code.
- **repository:** extend credential-literal and configured internal-host checks to
  docs, examples, fixtures and new unstaged files; keep diagnostics free of matched
  values and reject private environment files.
